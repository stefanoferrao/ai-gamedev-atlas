3D & rendering

8 concepts

How a 3D scene becomes pixels, and the standard ways to draw less of it.

01

Raycasting

ask a line what it hits

A raycast sends an invisible line from a point in a direction and returns the first object it touches. The result holds the hit point, the distance and the surface normal, shown here as the pink dot and the yellow arrow. Games use it for hitscan guns, line of sight, mouse picking and ground checks.

prompt bit
Use a raycast for hit detection: cast from the muzzle along the aim direction with a max distance of 100 units and a layer mask that skips the shooter, take the closest hit, and use its point and surface normal to place the impact effect.

02

Normals

which way a surface faces

A normal is a unit vector that points straight out of a surface. Lighting compares it with the direction to the light, so in the demo the faces whose normal lines point at the bulb are bright. Gameplay code uses the same vector to bounce objects off walls and to tell a floor from a steep slope.

prompt bit
Use the surface normal from each collision or raycast hit: reflect the velocity around it for bounces, and count a surface as walkable floor only when the normal's up component is above 0.7, which is about 45 degrees.

03

Level of detail

cheap mesh when it is far

Level of detail, or LOD, swaps a model for a simpler version as it gets farther from the camera. A far object covers only a few pixels, so the extra triangles of the full mesh would not show and only cost GPU time. The rock in the demo drops from 1280 to 80 to 20 triangles as it crosses each distance line.

prompt bit
Add LOD to the props: build three versions at about 100%, 30% and 10% of the triangles, switch between them at set camera distances, and add a 10% hysteresis band so a mesh standing near a threshold does not flicker between levels.

04

Frustum culling

skip what the camera cannot see

The frustum is the part of the world a camera can see, shaped like a pyramid with its tip cut off. Frustum culling tests each object's bounding volume against it and skips the objects outside, so the GPU spends no time on them. In the demo the camera turns, and only the boxes inside the cyan wedge are drawn solid.

prompt bit
Add frustum culling: each frame, build a frustum from the camera's projection and view matrices, test each object's bounding sphere against it, and skip both the draw and the animation update for objects fully outside.

05

Fragment shader

a tiny program per pixel

A fragment shader is a small program that the GPU runs once for every pixel a surface covers, to decide that pixel's colour. Each run gets its own inputs, such as the UV coordinate and the time, and thousands of runs happen in parallel. The magnifier in the demo shows the pixels as squares, each one the result of a separate run.

prompt bit
Write this effect as a GLSL fragment shader: compute each pixel's colour from its UV and a uTime uniform, and expose speed, scale and colours as uniforms so they can be tuned without touching the shader code.

06

Billboarding

always turn to face the camera

A billboard is a flat quad that is rotated every frame to face the camera. Health bars, damage numbers, name tags and distant trees are billboards, so they read the same from any angle. In the demo, the left health bar is fixed to its character and turns edge on or mirrored, while the right one stays readable.

prompt bit
Make the health bars and name tags billboards: each frame, set each quad's world rotation to the camera's rotation so it faces the screen, and for trees and other upright sprites rotate only around the Y axis so they stay vertical.

07

Quaternions

rotations that take the short way

Euler angles store a rotation as three turns around the X, Y and Z axes, and blending those three numbers one by one sends the object on a detour. A quaternion stores the same rotation as four numbers, and slerp blends two of them along the shortest arc at a steady speed. Both ships turn between the same two orientations, and the nose trails show a 371° tumble on the left against a clean 143° arc on the right.

prompt bit
Store rotations as quaternions, combine them by multiplication, interpolate with slerp and negate one of the two when their dot product is below 0 so it takes the short way, and convert to Euler angles only for display or editor input.

08

Z-fighting

two surfaces fighting for pixels

Z-fighting is the flicker you get when two surfaces sit at the same depth, so rounding in the depth buffer picks the visible one pixel by pixel. The depth buffer spends most of its precision close to the near plane, so a near plane at 0.01 instead of 0.1 leaves distant surfaces with ten times less room. On the left the yellow decal lies exactly on the ground and breaks into flickering stripes, while on the right polygon offset pulls it toward the camera and it stays solid.

prompt bit
Set the camera near plane as far out as the game allows, about 0.1, and the far plane as close as the view distance allows, never put two visible surfaces in the same plane, and lift decals about 1 cm along the surface normal or draw them with polygon offset, factor -1 and units -4.

09

Delta time

move per second, not per frame

Delta time is how long the previous frame took, in seconds. Multiply every speed by it and the game runs at the same pace at 30 fps and at 240 fps. Here the frame rate dips from 60 to 14 fps, and the racer that moves a fixed amount per frame falls behind.

prompt bit
Make all movement frame-rate independent with delta time: multiply every speed by dt in seconds, add dt to every timer, smooth with 1 - exp(-k * dt) instead of a fixed lerp factor, and clamp dt to about 0.05 s so one long frame cannot teleport anything.

10

Coyote time

a late jump that still counts

Coyote time lets the player still jump for a short window, usually 0.1 to 0.15 s, after running off a ledge. Players often press jump a few frames too late, and without the window the game ignores that press and they fall. Both runners here press jump at the same late moment, and only the one with coyote time clears the gap.

prompt bit
Add coyote time to the jump: track the time since the player last stood on the ground, allow a jump while it is under 0.12 s, and use up that window when the jump fires so the window cannot give a second jump.

11

Easing

bend linear motion into curves

An easing function maps linear progress from 0 to 1 onto a curve, so motion can slow down into its end point or overshoot and settle instead of moving at one constant speed. The plot on the left draws each curve, and each square on the right follows its curve over the same 1.5 seconds. Use it for any move with a known start, end and duration, such as a menu sliding in or a camera pan.

prompt bit
Replace linear tweens with easing: compute t = elapsed / duration clamped between 0 and 1, set position = lerp(start, end, easeOutCubic(t)), use about 0.3 s for UI moves, and switch to easeOutBack when the motion should overshoot slightly before settling.

12

Screen shake

one trauma value drives the shake

Screen shake moves the camera after a hit, driven by a trauma value from 0 to 1 that each hit raises and that falls back to 0 over about a second. The right view shakes by trauma squared times smooth noise, so the two light hits move a few pixels and the heavy hit moves far. The left view uses raw trauma and a new random offset every frame, so every hit jitters.

prompt bit
Drive screen shake from a trauma value between 0 and 1: each hit adds 0.3 to 0.6, trauma decays by about 1 per second, and each frame the camera x, y and roll offsets equal a max offset times trauma squared times smooth Perlin noise, not fresh random numbers.

13

Squash and stretch

shape shows speed and impact

Squash and stretch scales an object along its direction of motion. It stretches while it moves fast and flattens for a moment when it lands, and the other axis gets the inverse scale so its size looks constant. Both balls here follow the same bounce, and only the right one shows the speed and the impact in its shape.

prompt bit
Add squash and stretch to the sprite: scale it up to about 1.3 along its velocity when it moves fast, squash it to about 0.7 on landing and ease back to 1 within 0.15 s, give the other axis the inverse scale so its area stays constant, and pivot at the feet so it stays on the ground.

14

Camera deadzone

let the player move first

A camera deadzone is a box in the middle of the screen where the player can move while the camera stays still. When the player pushes past an edge, the camera moves just enough to keep them on that edge, so small steps and turnarounds leave the view steady. Here the camera holds still each time the player turns back and crosses the box.

prompt bit
Give the follow camera a deadzone: keep the camera still while the player is inside a centered box about a quarter of the screen wide, and when they cross an edge, move the camera by exactly how far they went past it.

15

Input buffering

an early press that still counts

Input buffering remembers a button press for a short window, usually about 0.1 s, and performs the action on the first frame it becomes possible. Players often press jump a few frames before they land, and without a buffer the game drops that press because the character is still in the air. Both characters here press jump 0.08 s before landing, and only the one with a 0.1 s buffer jumps on the frame it touches down.

prompt bit
Add a jump input buffer: when the player presses jump, set a buffer timer to 0.1 s that counts down every frame, fire the jump on the first frame the player is grounded while that timer is above 0, and reset the timer to 0 when the jump fires so one press gives one jump.

16

Acceleration and friction

speed builds up and bleeds off

Acceleration and friction move the velocity toward the input speed by a set amount per second, instead of setting it in one frame. The bottom character reaches full speed in 0.2 s, stops 0.1 s after release, and brakes twice as hard when the input flips direction. The top character copies the input directly, so its speed trace is a square wave and it starts, stops and turns around in a single frame.

prompt bit
Give horizontal movement acceleration and friction: each frame move the velocity toward input times max speed with an acceleration that reaches max speed in 0.1 to 0.2 s, decelerate to a stop in about 0.1 s when no direction is held, use twice that deceleration when the input points against the current velocity, and halve both rates while airborne.

17

Hit stop

freeze both fighters on impact

Hit stop pauses the attacker and the target for 50 to 100 ms when a hit lands. Without it, the blade crosses the target in 2 or 3 frames and the contact is hard to see. The bottom swing freezes for 120 ms, a bit longer than usual so you can see the gap in its timeline, while the sparks keep moving.

prompt bit
Add hit stop: when a hit lands, pause the animation and movement of the attacker and the target for 50 to 100 ms scaled by the damage, keep reading and buffering input during the pause, and keep UI and particles running at normal speed.

18

Invincibility frames

brief safety after each hit

Invincibility frames, or i-frames, are a window of 0.5 to 1 s after a hit during which the character ignores further damage. Without them, a bolt that overlaps the character for 9 frames deals damage on all 9, and three bolts empty the top health bar. The bottom character takes one hit, gets knocked back, and blinks for 1 s while the next bolt passes through without dealing damage.

prompt bit
Add invincibility frames: after the player takes damage, ignore all further damage for 0.5 to 1 s, blink the sprite on and off at about 10 Hz during that window, and apply a knockback impulse that pushes the player away from the damage source.

19

Object pooling

allocate once, reuse forever

A pool creates a fixed set of objects once and reuses them instead of creating a new one for every bullet. In C# or JavaScript each discarded object becomes garbage, and the garbage collector pauses the game to clean it up. The top lane stalls on those pauses while the pooled lane recycles the same 14 slots.

prompt bit
Use an object pool for bullets and particles: preallocate the peak count up front, take an inactive instance and reset its fields on spawn, mark it inactive on death instead of destroying it, and log a warning if the pool ever runs out.

20

Finite state machine

one state at a time

A finite state machine keeps a character in exactly one state and lists which events move it to which state. An event with no matching transition is ignored, like the attack pressed in mid air here. This replaces a pile of booleans like isJumping and isAttacking that can end up true at the same time.

prompt bit
Model the character with a finite state machine: one active state at a time, an explicit transition table keyed by state and event, events with no entry ignored, and enter, update and exit hooks on each state.

21

Hitbox and hurtbox

what hits, what gets hit

A hitbox is the area of an attack that deals damage, and it exists only during the attack's active frames. A hurtbox is the area of a character that can take damage. A hit lands only when the two overlap, so the defender's duck here makes every second swing miss.

prompt bit
Separate hitboxes from hurtboxes: enable each hitbox only during the attack's active frames, test it against the target's hurtboxes instead of sprite bounds, and register at most one hit per target per swing.

22

A* pathfinding

search that aims at the goal

A* searches a grid by always expanding the tile with the lowest cost so far plus an estimate of the distance left. The estimate steers the search towards the goal, so in this maze it expands about 40% fewer tiles than a blind search. As long as the estimate never overestimates, the path it returns is still the shortest.

prompt bit
Use A* on the navigation grid with a binary heap for the open set, g as the cost so far, a Manhattan heuristic for 4-way movement or octile for 8-way, ties on f broken towards lower h, and the path rebuilt from parent links when the goal is popped.

23

Particle system

one emitter, many short lives

A particle system spawns many short-lived sprites from one emitter and a handful of numbers: emission rate, lifetime, direction spread, speed, gravity and drag. Each particle also changes size and opacity over its own life. The sparks, smoke and confetti here are the same code with different numbers.

prompt bit
Build this as a particle system: one emitter with tunable emission rate, lifetime range, direction spread, initial speed range, gravity and drag, size and opacity curves over each particle's life, and particles taken from a fixed preallocated pool.

24

Fixed timestep

physics on a steady clock

A fixed timestep advances physics in constant slices, here 1/60 of a second, whatever the frame rate. Each frame adds its duration to an accumulator and runs as many slices as fit, carrying the rest to the next frame. The top spring steps by the raw frame time instead, so a short burst of 92 ms frames makes it gain energy and explode.

prompt bit
Run physics on a fixed 60 Hz timestep: add each frame's delta time to an accumulator capped at 0.25 s, step the simulation by 1/60 s while the accumulator holds at least that much, and draw objects interpolated between the last two physics states using the leftover fraction.

25

Steering behaviors

nudge velocity toward a goal

Steering behaviors move a unit by adding a force each frame that turns its current velocity toward a desired velocity, capped at a max force. Arrive lowers the desired speed inside a slowing radius, here the dashed circle, and separation pushes units apart when they get too close. On the left, eight units run at the target at full speed, overshoot it, flip back every frame and pile onto one point, while the eight on the right slow down and settle around it.

prompt bit
Move units with steering behaviors: each frame compute steering as desired velocity minus current velocity, clamp it to a max force of about 4 times the max speed per second, and add it to the velocity; for arrive, scale the desired speed by distance divided by a slowing radius of about 4 unit widths, and add separation that pushes away from each neighbour closer than about 2 unit widths, harder the closer it is.

26

Tunneling

fast objects skip through walls

Tunneling happens when an object moves so far in one frame that it is in front of a wall before the step and behind it after, so a per frame overlap test never sees them touch. Here the bullet moves about 40 px per frame against a 6 px wall, and each dot marks one frame, slowed down. The top lane tests overlap only at the dots and lets the bullet through, while the bottom lane tests the whole segment between two dots and stops it at the wall.

prompt bit
For fast objects like bullets, test the swept path from last frame's position to the new one with a raycast or shape cast, or sub-step the physics so each step moves less than half the object's size, and turn on continuous collision detection for fast rigidbodies.

27

Seeded noise

same seed, same world

Seeded noise builds a world from a seeded random number generator, so the same seed always rebuilds the same world and a save only needs to store that one number. The top strip picks each of its 64 column heights with Math.random, so it is jagged and different on every regenerate. The bottom strip sums 4 octaves of value noise from a seeded generator, so its hills are smooth, the same seed redraws them exactly over the dashed outline, and a new seed gives new hills.

prompt bit
Generate the world from a seeded PRNG such as mulberry32 feeding 2D Perlin or simplex noise with 3 to 5 octaves, each at double the frequency and half the amplitude of the one before, store the seed in the save file, and never call Math.random in world generation.

28

Frame budget

16.67 ms, and where it goes

At 60 fps the game has 16.67 milliseconds to finish each frame, and input, game logic, physics and rendering all share that time. A frame that takes longer misses the screen refresh, and the player sees a stutter. Measure how long each system takes and fix the largest one first, like the physics spikes that push frames over the red line here.

prompt bit
Before optimising, time input, update, physics and render every frame with performance.now(), show each one in milliseconds against the 16.67 ms budget for 60 fps, and optimise the largest one first.

29

Draw calls

one call, four hundred crates

A draw call is the CPU telling the GPU to draw one mesh, and the CPU spends time preparing each one. Instancing draws many copies of the same mesh and material in a single call, with a list of positions and rotations for the copies. The animation draws the same 400 crates both ways, and the count drops from 400 calls to 1.

prompt bit
Use GPU instancing for repeated objects that share one mesh and one material, so each group renders in a single draw call with a per-instance transform buffer, and merge static meshes that share a material into one mesh.

30

Spatial partitioning

only test what is nearby

Checking every pair of objects for collisions costs the square of the object count. The 48 objects here need 1,128 checks a frame, and 1,000 objects would need about 500,000. A spatial grid sorts objects into cells by position and tests each object only against objects in its own and neighbouring cells, which finds the same overlaps here with about 100 checks.

prompt bit
Use a uniform spatial grid for broad-phase collision with cells about twice the size of the largest object, rebuild it every frame, and test each object only against objects in its own cell and the 8 neighbouring cells.

31

Overdraw

the same pixel, shaded again

Overdraw is the number of times the GPU shades the same pixel in one frame. Transparent sprites cannot hide what is behind them, so every layer of a smoke stack is shaded, and large sprites close to the camera cost the most. The overdraw view counts the layers on each pixel, from blue for one layer to white for eight or more.

prompt bit
Reduce overdraw from transparent particles: cap how many can overlap, keep each sprite small on screen, trim sprite quads tightly around their visible pixels, and render heavy effects like smoke to a half-resolution buffer.

32

Time slicing

spread the work across frames

Time slicing spreads expensive work over several frames instead of running all of it every frame. Here 192 agents are split into 8 buckets, and each frame only one bucket, the lit cell under the cost bar, picks a new target, while all of them keep moving every frame. At 60 fps each agent now re-decides 7.5 times a second instead of 60, and the frame drops back under the 16.67 ms budget.

prompt bit
Time-slice expensive AI updates by splitting agents into 4 to 8 buckets by index and running decisions like pathfinding or target selection for one bucket per frame, while movement and animation still update every frame.

33

Texture atlas

one texture, one draw call

A texture atlas packs many small images into one large texture, and each sprite keeps the UV rectangle of its own region. The GPU has to start a new batch every time the bound texture changes, so these 24 sprites cost 22 draw calls when each of the 6 sprite types has its own texture. Packed into one atlas, the same 24 sprites in the same order draw in 1 call.

prompt bit
Pack the sprites into one texture atlas, for example 2048 by 2048 with 2 px of padding around each sprite, store each sprite's UV rectangle in a JSON file, and draw every sprite that shares the atlas and shader in a single batch.

34

Chunk streaming

load only what is near the player

Chunk streaming splits a large world into fixed-size chunks and keeps only the chunks near the player in memory, here 8 to 14 of the 98, the same count a world of 10,000 chunks would need. Chunks load inside the solid circle and unload only outside the larger dashed one, so the player pacing on a chunk border causes no reloads. With a single radius, the same pacing drops and reloads chunks 8 times in 2 seconds.

prompt bit
Stream the world in fixed-size chunks of 32 by 32 tiles, keep every chunk within 2 chunks of the player loaded, load new chunks asynchronously off the main thread, unload a chunk only once it is more than 3 chunks away so a player standing on a border does not cause reloads, and reuse chunk objects from a pool.
